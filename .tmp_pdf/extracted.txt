Overview
In the previous activity, you built your personal portfolio website. In this activity, you will convert your
portfolio into a Laravel + Inertia.js + React application and make one section of it dynamic by
building a complete CRUD (Create, Read, Update, Delete) feature with proper validation.
Instead of hard-coding the content of that section, its data will now be stored in a database and managed
through forms. Visitors still see your portfolio as before, but you can now add, edit, and remove content
without touching the code.
Building the CRUD is only part of the task. You must also be able to explain how it works and why you
built it that way.
Learning Outcomes
By the end of this activity, you should be able to:
1. Convert a static website into a Laravel + Inertia.js + React application.
2. Build a working CRUD feature using a migration, an Eloquent model, a resource controller,
routes, and Inertia React pages.
3. Design server-side validation rules and display validation errors properly in the React UI.
4. Explain the request flow of a Laravel + Inertia application from route to rendered page. 5.
Justify the design decisions behind your implementation.
Part 1 - Convert Your Portfolio
1. Create a new Laravel project with Inertia.js and React (use the starter setup discussed in class).
2. Move your existing portfolio into the project as React pages and components. Break repeated
parts into components (e.g., Navbar, Footer, SectionTitle, Card).
3. Keep your original design. Use Tailwind CSS for styling.
4. Your public portfolio page must still display correctly after conversion.

Part 3 - Build the CRUD
Your CRUD feature must meet these minimum technical requirements:
1. Migration: Creates the table for your chosen section with at least 5 meaningful fields.
2. Model: An Eloquent model with a properly defined $fillable property.
3. Controller: A separate resource controller for your section (e.g., ProjectController,
SkillController) with index, create, store, edit, update, and destroy methods.
4. Routes: Registered in routes/web.php using Route::resource() (or explicitly defined routes that
you can justify).
5. Validation: At least five different validation rules across your fields, including:
a. required
b. a length or size rule (max, min, between)
c. a type or format rule (numeric, integer, date, url, email, etc.)
d. a unique rule that correctly ignores the current record on update, if applicable to your
fields
e. for image uploads: image, mimes, and max file size
f. at least one custom error message
6. React Pages: At minimum Index, Create, and Edit pages inside
resources/js/Pages/[YourSection]/.

7. Components: At least one reusable component (e.g., a shared form used by both Create and Edit,
or an input with an error message).
8. Error Display: Validation errors must appear beside the related field, and the values typed by the
user must not be lost when validation fails.
9. Feedback: A success message after create, update, and delete.
10. Delete Confirmation: A confirmation step before a record is deleted.
11. Public Display: The records you manage must appear in that section of your public portfolio
page.
Bonus (optional): search or filter, pagination, drag-to-reorder or display order, a Show page, or login
protection for the management pages.
Part 4 - Test Your Validation
Prove that your validation works. Create a Validation Test Table with at least six test cases, for
example:
• Submitting the form with all fields empty
• Exceeding the maximum length of a text field
• Entering the wrong data type or format (e.g., letters in a number field, invalid URL) •
Entering a duplicate value in a field that must be unique
• Updating a record without changing its unique field (it should still save)
• Uploading a file that is not an image, or an image that is too large
